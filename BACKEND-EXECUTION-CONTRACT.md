# DOC execution contract — independent native compiler, WebGPU/WGSL only

## Current independent profile (2026-11-28)

Active development is `everhush/DOC`, with `runtime-doc/` the independent DOC-authored compiler and native runtime, and `runtime-rust/` frozen as reference/bootstrap. The original Rust-only statements below are historical profile-specific provenance. The finite kernel and prior submitted versions remain unchanged; revised manuscript sources on master describe a separate conditional generation construction.

- Ordinary compiled managed-reactive executables default to CPU; `--backend=cpu` selects CPU, `--backend=gpu` is strict, and `--backend=auto` enables automatic heterogeneous placement. The last two require a GPU-enabled build for actual GPU execution. If the adapter is unavailable before work, auto may select CPU unless physical GPU is explicitly required; explicit GPU rejects. Once work has been admitted or a device fault invalidates an attempt, do not publish an incomplete candidate or silently retry it as CPU.
- CPU capacity is derived from process affinity and cgroup quota and admitted independent work. Optional `DOC_WORKERS` is an external cap/measurement control, not authored placement. Nested pools are suppressed. No fixed application-wide worker ceiling or workload-specific scheduling hints.
- Physical realization uses compiler-emitted typed WGSL and the pinned WebGPU ABI only. DOC source does not choose native GPU APIs, drivers, or hardware names. Provider limits and typed range proof determine admission; strict mode rejects unsupported work. Test infrastructure can inspect adapter class to prove real hardware and provision host graphics; it is not DOC-level hardware policy.
- Runtime-sized finite lexical families use a checked region byte budget instead of the old fixed lane cap. Compiler/source/causal and device buffer limits remain independently enforced. GPU group count is derived from admitted lanes and actual negotiated device limits; the 64-invocation local width is not a total thread cap. Grid-stride execution covers admitted lanes beyond one-dimensional dispatch extent. No manual group cap in production.
- The automatic placement heuristic is generic but does not promise globally optimal profitability. Cheap maps and reductions can be slower than serial CPU; preserve negative results. CPU/GPU use the same typed semantic, source-epoch, private-candidate, rollback and stable observation contract. The shader subset is bounded scalar bool/signed-32-bit and admitted lexical families, not arbitrary effects, managed structures or recurrence.
- Current production runtime tree `a7fe0554abea1a2b218929b33ad2f8f66f632f94`, compiler tree `9120f50dde55af7c0a656d43ece6acf824cbcab0`. Physical preflight 46053188589 and original-workload CPU 46053929420 passed; full exact same-run validation 46052437755 passed all six jobs. See [autonomous scaling audit](https://github.com/everhush/DOC/blob/9491ca31303579b2ce223e344dee9b8b5354214f/verification/AUTONOMOUS-SCALING-AUDIT.md). No new software GPU measurements or public release is inferred.

## Historical frozen reference profile

# DOC active execution contract — Rust reference, WebGPU/WGSL only

**Current #15 reconciliation (2026-11-25).** Initial host Linux x86_64. Active development rtu0/doc2/main; Rust is the reference/bootstrap, Goose is historical and excluded from active CI. The independent DOC implementation belongs in runtime-doc/ only after the audited Rust handoff. The normative manuscript is unchanged. This contract distinguishes actual supported entry points and does not promise final self-hosting or universal GPU coverage.

## Entry points and placement

- Standalone `doc FILE.doc` defaults to CPU. Its first optional selector is strictly `--backend=cpu|gpu`; it rejects `--backend=auto` and arbitrary selectors. See runtime-rust/src/main.rs:118–128. Selected GPU must execute admitted work on wgpu or fail, not secretly use CPU for the claimed shader.
- Automatic heterogeneous placement is implemented through AutomaticScheduler and Runtime::stabilize_automatic, used by automatic recurrence, game/scene hosts and dependency-family proofs. It is not an authored placement directive or an extra source-language mode. Independent ready scalar work may be split into CPU and GPU candidates by typed eligibility, actual adapter admission and conservative grain (64 lanes); nonadmitted work remains CPU. Initial absence/unavailability may choose a reported CPU-only path; after dispatch starts failure rejects the private candidate. The standalone CLI does not expose automatic mode at this revision; do not infer automatic support at every entry.
- CPU worker count and task grain are host/evidence controls, not DOC source. Hardware-limited scoped workers evaluate a common pre-valuation; join and validate all results before frontier publication. C Stage-0 CPU compilation is a separate bootstrap profile; it does not implement the final independent GPU compiler.
- `wgpu::Instance::default()` chooses the platform provider. No DOC-level native API/driver/manifest/ICD selection or inspection. WebGPU-exposed device class, limits and errors determine admission. A discrete/integrated adapter may certify hardware execution; CPU adapter only through explicit software-test allowance, never as physical evidence.
- The current Rust compute path specializes typed source expressions into generated WGSL (src/wgsl.rs:302; src/gpu.rs:297–318), not a permanent instruction interpreter. Device-local bounded cache keys by complete generated shader source; dispatch buffers are private, error scope and readback completion precede candidate publication. Graphics uses DOC-authored generated mesh shaders (graphics.rs, scene_gpu.rs), separately from pure computation.
- Pure eligible bool/signed-i32 fragments only. Range/unsupported operation/type checks and WebGPU buffer/device limits fail closed. Automatic CPU selection for unprofitable/ineligible work is not strict GPU fallback. Source authority, native effects and dependent recurrence boundaries remain ordered by actual dependencies; no promise that arbitrary effects or values run in a shader.
