# DOC mesh graphics — first compiler slice

This is an initial foundation for #21, not a completed 3D game. The two ordinary DOC graphs in `engine/graphics/` describe fixed-point homogeneous clip position and normal-dependent color. The compiler reuses checked DOC Graph and Expr, emits WGSL vertex and fragment entry points, resource layout, varyings and pixel encoding. Authoring WGSL is unnecessary. The platform binds typed mesh and draw data, checks domains/index bounds, and uses native WebGPU rasterization and depth. Test shader mutation changes actual GPU pixels, and depth rejects a farther triangle even when submitted later. The current supported subset is total scalar int/bool expressions; 12 vertex words, 8 draw words, 3 flat varyings, 3 color channels. It is not general floating/vector/matrix geometry yet, does not implement mesh loading or an interactive game, and uses deliberately bounded fixed-point clip coordinates. The current ABI is expressed in host-side bindings as a temporary foundation; DOC-authored scene/mesh/material/camera bindings and reusable geometry/physics functions must replace application-specific host mappings. No hidden GPU compute fallback. No claim of physical GPU proof until the hardware check is integrated and run. Future #11 must preserve these semantics without depending on this Rust frontend/runtime. Keep 2D only as existing regression tests.
