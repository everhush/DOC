# DOC AOT — Stage 0 scalar C backend (Issue #11)

The original scalar Stage-0 slice passed both Linux CI jobs at b8f3e83 (run 45329054988). This is the next typed-collection candidate. The Rust frontend validates and elaborates the same typed graph exported by [DOC-TYPED-IR/1](DOC-TYPED-IR-V1.md); the compiler emits specialized C functions for each authored derive, static dependency levels and direct invalidation/ancestor closure code. No parser, evaluator, bytecode, Rust or Goose runtime is linked into the generated program. GCC/Clang C11, checked-overflow builtins and POSIX threads are build/platform dependencies. Linux x86_64 is the initial target.

```sh
cargo build --release --manifest-path runtime-rust/Cargo.toml --bin doc-compile
runtime-rust/target/release/doc-compile runtime-rust/examples/repair.doc \
  --emit-c /tmp/repair.c --emit-ir /tmp/repair.ir --out /tmp/repair-native
/tmp/repair-native a=4 b=1
/tmp/repair-native --demand=chosen a=4 --next --demand=chosen a=4 --next a=5
```

Output paths must be new. The compiler uses CC (one executable path, no shell), or cc by default. The generated executable accepts the reference scalar source=value, --backend=cpu, --demand=STATE, --through=N, --until=BOOL --max-epochs=N, carry and --fact=EPOCH:name=value CLI forms. --next separates successive private update batches for the static graph and prints epoch indices; dirty states, exact cutoff and pending demand are retained. Invalid batches or failed calculations terminate without publishing the candidate output. Recurrence uses fresh default facts plus explicitly authorized carry/facts. The selected expression of if is evaluated lazily; checked i64 operations do not use signed-overflow UB. Booleans are validated, not arbitrary integers.

Independent dirty states in each static level may use real bounded native threads (hardware affinity and task grain, no separate fixed worker ceiling); all results finish before committing that level into the private candidate. Thread admission failure runs remaining tasks on CPU serially and reports actual launched workers. The level schedule is conservative rather than the maximal dynamic ready antichain. DOC_WORKERS is an evidence/test control, not authored placement. DOC_AOT_EVALUATIONS and DOC_AOT_PARALLEL_FRONTIER are stderr traces. This stage has no GPU implementation; --backend=gpu fails explicitly, never silently falls back.

Current supported types int, bool, ints, maybe_int, text and nat; checked add/sub/mul, eq/lt/le, if, typed premises/literals, collection get/try_get, len, append, tail, remove_at, replace_at, some/none and eager unwrap_or. Collections use immutable list buffers (65,536 elements per value, 16 MiB temporary arena per derive); every derive clones its result before discarding temporary allocations, workers only read the prior valuation, and the candidate frees all owned buffers on failure. Exact cutoff compares list contents, not addresses. Pure frontend-elaborated functions/imports work. Runtime effects are still rejected unless explicitly opting into `--freeze-startup-assets`: the existing frontend validates and samples typed startup asset facts at build time, then the compiled binary uses those frozen defaults. This is not runtime I/O or reload-file support. The existing Radar Chase graph is now a native CPU recurrence differential test against the full Rust typed-state trace over 16 epochs, with the same carry/facts and original DOC source. This is an intermediate graph test, not a completed native game host. Dynamic graph replacement, durable checkpoints, full resource/lifetime protocols, asynchronous readers, cancellation APIs, runtime file/audio effects, compiled GPU, DOC-authored compiler/runtime and Stage1→Stage2 bootstrap are **not yet implemented**. The C platform/transaction support is a temporary Stage-0 implementation, not a claim that it is DOC-authored. No claim of performance improvement. CI runs differential tests against the Rust reference, real C compiler, ELF clean-directory launch, source updates and invalid inputs, demand cutoff, recurrence and failed epochs; records source/executable size, link dependencies, build/run measurements and toolchain provenance. Keep issue #11 open until its complete acceptance criteria pass.

## Pure-type and memory-policy candidate (DOC-AOT-C/2)
All six existing pure types and expression forms now have native lowering candidates. Text uses exact validated UTF-8 bytes; length is byte length. Naturals use canonical decimal storage, checked subtraction and arbitrary precision within explicit resource bounds (65,536 bytes/digits, 16,777,216 digit-products per multiplication). Excess capacity fails closed, not fixed-width wraparound. Immutable buffers have one owner; temporary arena values are copied before arena reclamation. Aggregate atomic byte/call counters are diagnostics, **not** object reference counts and never decide reclamation. DOC_AOT_MEMORY_TRACE=1 records live/peak/allocated/freed payload bytes at commits and exit; DOC_AOT_FAIL_ALLOC_AT=N injects allocation failure (deterministic site order at one worker). Added all-type Rust differential tests, complete single-worker allocation failure sweep, 2,000-epoch reclamation and actual generated-C ASan/UBSan/LSan smoke. These are candidates until exact CI passes. Protected asynchronous readers, dynamic generation retirement, GPU completion and full game effects remain separate open gates under #11/#13. Rust reference safety stays intact. No collector or reference counts in this C value path; not yet a complete native-runtime proof.

Run `./native --asset-root=/path/to/engine --through=...`; default root is current working directory. ## Native scalar object ABI (initial #24 foundation)

```sh
doc-compile scalar.doc --object arithmetic --emit-c arithmetic.c --emit-header arithmetic.h --out arithmetic.o
```

The freestanding profile emits a platform C-ABI callable function `doc_export_arithmetic` and matching result struct declaration. It accepts typed source arguments (int64_t for int, uint8_t restricted to 0/1 for bool) in declaration order, plus a caller-owned aligned writable result region. All graph states are exported as named fields, with target ABI alignment/padding. No writes occur until the entire private dependency calculation succeeds; return 1 on success, 0 on null result, noncanonical boolean, or checked arithmetic failure. The caller must supply valid storage and synchronize any concurrent access. This is not an arbitrary pointer-safety guarantee across FFI. No evaluator, allocation, pthreads, host libc or dynamic loader is required by the initial Linux x86_64 scalar object. It shares checked expression lowering and exact word helpers with the existing hosted backend. Unsupported types, dynamic expressions and startup effects fail closed. State budget 256; no arbitrary ABI import, native effect, interrupt or hardware access yet. The independent test links the object into an actual static Linux ELF without libc, checks ABI, overflow/rollback and absence of unresolved dependencies, then executes it after deleting source. This is a freestanding process test using the Linux kernel, **not a bare-metal boot proof**. The test-only entry stub is not DOC application policy. Next: typed source-declared imports, effect/region authority, target intrinsics and minimal boot proof. Final #11 must reproduce the boundary without the bootstrap Rust compiler.

## Typed imported native calls (initial #24 effect profile)

See `runtime-rust/examples/native_socket.doc`. Compile with `--object network --emit-header net.h --emit-c net.c --emit-ir net.ir --out net.o --allow-native-import socket --allow-native-import close`. The generated object directly references the existing target symbols; no handwritten wrapper is needed. This Linux example creates and closes a local socket without sending network traffic; test-only C verifies the exported ABI and actual closed descriptor. The caller links the appropriate target libraries. Native import signatures are trusted declarations, not a verifier of arbitrary foreign machine code; the build caller must grant each exact symbol, and is responsible for matching target ABI and permissions. GNU C aliases are currently used for symbol names. ABI types i64/i32/u32/u8 map to DOC int; bool8 maps to DOC bool (not C _Bool); narrowing and noncanonical boolean returns are checked. All call arguments must be named typed premises; additional premises provide causal completion edges. Every native call in this initial profile must be ordered with every other through actual dependencies, not source order. Native effects execute once per export invocation, are neither memoized nor replayable, and are **not rolled back** if a later call or derive fails; the result struct is written only upon successful completion. External handles in this initial profile require explicit privileged resource management, as shown by close; automatic managed handles and conditional cleanup are not yet implemented. Pointer, callback, volatile/atomic/intrinsic and arbitrary native layout features remain outstanding. Ordinary reference evaluation rejects this profile. Native IR uses a separate DOC-NATIVE-IR/1 header, explicit import rows (index, symbol, ABI parameter list, ABI result) and call rows (state id, name, DOC kind, all premise ids, import index, ABI argument state ids); pure source/derive rows retain the existing grammar. It never serializes the private type-checking placeholder as a pure value. No claim of full ABI or freestanding boot acceptance yet.

## Controlled region effects (initial #24 memory boundary)

`runtime-rust/examples/native_regions.doc` declares native regions and operations directly in DOC. Build the object with `--allow-native-region device --allow-native-region counter`. Each granted region adds a caller-supplied `void *` and `size_t` element count to the export ABI. Supported element types are i64/i32/u32/u8; access is plain, volatile or atomic (initially lock-free u32 only). `native load` returns a DOC int, `native store` returns a completion bool, `native fetch_add` returns the old u32 value as an int and wraps modulo 2^32, and `native fence ... = seq_cst()` is a sequentially consistent atomic fence. Atomic load/store/RMW/fence use explicit seq_cst C11 ordering; volatile accesses are not atomics or synchronization. Region operations and foreign calls share the explicit causal effect chain. Operands must be named integer premises, with checked narrowing and element bounds. Before any effect, region count multiplication, address range, alignment and pairwise non-overlap (including the result struct) are validated. The caller still must provide actually valid live storage with matching ABI, and appropriate synchronization for plain/volatile access; arbitrary foreign addresses cannot be made safe by integer checks alone. Atomic storage must have the target atomic type and be initialized. No DOC-managed pointer lifetime or manual allocation is introduced for ordinary values. Region effects are not reversible if a subsequent operation fails; the result struct remains unpublished. Native IR adds region rows and region-op rows with explicit access/operation and dependency ids. Tests use actual volatile storage, lock-free atomic operations, wraparound, alignment/bounds/authority rejection and effect-vs-publication failure behavior. A volatile region can be mapped by a privileged caller to MMIO; actual device proof and target intrinsic mechanism are still outstanding. This does not claim a finished safe FFI or hardware abstraction.

All scalar object exports check the result pointer's nullness, alignment and nonwrapping numeric extent, and validate/capture every external scalar source before executing any native effect, regardless of graph traversal order. The trusted caller still owns the obligation to supply live storage of the correct size and type; numerical address validation cannot prove that an arbitrary foreign address is mapped or writable. An invalid external boolean or result address must never execute an effect. A later failure after a valid effect is still not external rollback.

## Compiler-relevant structured token table (#24 candidate)

The DOC-authored `runtime-rust/examples/lexical_runs.doc` uses independent per-byte classifications followed by an input-dependent causal derivation to produce dynamically sized tagged triples (kind, byte offset, byte length) referencing the original UTF-8 byte buffer. This is a constructive encoding of a tagged variable-payload token collection, not a claim of general statically typed records, sums or a complete lexer. The subset recognizes ASCII letters/underscore, decimal digits, spaces, plus and equals; adjacent bytes of the same class form one run, and unsupported bytes fail without publishing a successor. No raw pointer, explicit allocation, programmer thread scheduling or handwritten native lexer. The regression compiles unchanged DOC to native C/ELF, checks an independent Rust test oracle as well as reference/native parity across worker counts, growth/shrink repair, invalid input and native allocation reclamation. The parallel classification uses the existing bounded dependency-family mechanism (4096 lanes); causal grouping uses the existing recurrence bounds. This implementation has not yet been validated by CI at commit creation. General structured type safety, richer collections and native resource/intrinsic foundations still require closure.

### Reference/native incremental CLI parity

The Rust reference CLI now accepts repeated `--next` batches using the same observation protocol as generated native programs: optional leading `--demand=STATE` per batch, typed source assignments, incremental stabilization, and one numbered observation only after the requested subgraph or whole graph stabilizes. A failed batch terminates without publishing its successor; already emitted observations remain available. The CLI's observation index is not the internal source epoch (unchanged assignments may have no source change). This is invocation-local fail-stop observation semantics, not a new externally persistent transaction API. Regression tests compare the existing native and Rust paths across demand changes, growth/shrink token tables, duplicate/derived/unknown/mistyped assignments and a failed full observation. Explicit GPU mode remains strict and does not acquire this CPU-only driver. CI validation pending at commit creation.

### Conditional native imported effects (#24)

The native object profile admits `native call result: int (arg,guard,fallback) = symbol(arg) when guard else fallback`. The guard must be a named bool premise and the fallback a named premise of the DOC result type (int or bool). All premises are evaluated before the effect; this is conditional dispatch, not lazy evaluation of the prerequisite subgraph. A false guard copies the scalar fallback and performs neither ABI argument narrowing nor the foreign call. A true guard retains all existing checked conversions and result validation. Both paths supply the declared completion dependency; calls remain strictly causally ordered, granted by the trusted build caller, and non-replayable. The native IR adds a distinct `call-if` row with the existing call fields followed by guard and fallback state IDs. Unconditional rows are unchanged. The example `native_conditional.doc` expresses conditional acquisition and release without a per-resource compiler adapter. The independent native C fixture checks skipped calls, acquisition failure, narrowing rejection, invalid booleans, actual release count and no live fixture resources on these paths. This is NOT automatic cleanup on arbitrary subsequent failure: a foreign call or checked derive failing between acquire and release can still prevent release, and external effects are not transactional. General managed external resource cleanup and target-intrinsic extensibility remain open. CI pending at commit creation.

### Invocation-scoped native handles (#24)

`native cleanup acquired = release_handle` attaches a destructor to an imported
call state returning ABI i32. The caller must grant the separate destructor
symbol with the C ABI `void release_handle(int32_t)`. Several acquisitions may
use the same destructor. It cannot also be imported for ordinary calls.
A successful dispatch owns each nonnegative result (including zero). Negative
results and skipped calls own nothing, even if the fallback is nonnegative.
The generated export keeps one local slot per acquisition and calls destructors
in reverse dependency order before publishing outputs or returning a checked
failure. The native IR records each association as a cleanup-i32 row containing
the acquisition state ID and destructor symbol. See `native_scoped.doc`.

The caller vouches for the ABI and for fresh ownership on each successful
acquisition. Other granted functions may use these handles during the call,
but must not consume or retain them. Exported integers describing acquisitions
are historical values after return. Destructors must complete normally and
release their resource without a recoverable error. Process exit, foreign
nonlocal jumps, and rollback of earlier external effects are outside this
contract. Ordinary DOC values and their memory model are unaffected.

### Extensible target-intrinsic calls (#24)

The built-in `popcount`, `leading_zeros` and `trailing_zeros` operations cover
portable word proofs. Target-specific code can additionally declare a typed
external intrinsic, for example:

```doc
native intrinsic target_transform(i64,bool8) -> i32 = external(target_transform)
native call transformed: int (input,enabled) = target_transform(input,enabled)
```

The build caller grants `target_transform` with
`--allow-native-intrinsic target_transform`. The compiler emits a restricted
C ABI declaration, checks every argument's range and canonical boolean value,
keeps the call in the explicit dependency chain, and validates the result
before the output publication barrier. `DOC-NATIVE-IR/1` records the
intrinsic symbol, operation descriptor and premise IDs. Untrusted symbols,
mismatched ABI kinds, out-of-range inputs and noncanonical results fail
closed. This is a narrow target/toolchain boundary for registers, instructions
or event APIs; it does not permit inline assembly, arbitrary pointers or
unverified foreign code, and portable DOC remains independent of any one
target symbol.

The complete fixture is `runtime-rust/examples/native_intrinsic_external.doc`;
its generated object is link-tested against an independent C target function,
including rejection of a noncanonical bool and a value outside the `u32`
argument range before the external call is entered.

External intrinsic grants are separate from ordinary import/destructor grants: neither flag authorizes the other category, and overlapping, duplicate or unused grants fail closed. The combined symbol grant budget remains 64, and intrinsic signatures share the 32-argument import bound. The native IR now includes an intrinsic declaration row containing its local name, ABI parameter list, result ABI and operation descriptor; call rows retain their previous representation. This preserves narrowing and boolean ABI information for future independent lowering. Regression tests exercise the exact arity boundary, wrong grant category, overlapping/unused grants, destructor isolation and no output creation on CLI authorization failure. New CI validation is required.

### Bounded foreign byte views and external event entry (#24 closure candidate)

An imported or external-intrinsic parameter `bytes` (mutable) or `const_bytes` (read-only) lowers to a C pointer plus `size_t` byte length. A call supplies three operands in place of that parameter: granted plain u8 region name, named integer offset premise and named integer count premise. Example:

```doc
native region buffer: u8 plain
native import read(i32,bytes) -> i64
native call received: int (fd,offset,count) = read(fd,buffer,offset,count)
```

The build grants both the region and symbol separately. Every dispatched call checks offset/count nonnegative, offset <= region capacity, count <= remaining capacity, before pointer formation and dispatch. Zero-length at end is valid; zero capacity permits a null pointer, without arithmetic on null. At most one view of each region per call (conservative disjointness); region address/alignment/extent/nonoverlap and all input bools are validated before any effect. Volatile/atomic/non-u8 regions cannot be passed to this interface. A skipped conditional call does not narrow or form a view. Views are not graph values, cannot be returned, and are valid only until the foreign function returns; the trusted foreign function must honor mutability, length, ownership and no retention. This is not a sandbox for arbitrary foreign code. Results remain scalar. Physical C ABI arguments (including expanded pairs) are capped at 32.

DOC-NATIVE-IR/1 records parameter types bytes/const_bytes and encodes each buffer argument as r:region-index:offset-state-id:count-state-id in the comma-separated argument list. Scalar arguments retain numeric state IDs; a reader without the extension must reject unknown parameter/argument forms. All effect ordering, irreversible side-effect and cleanup rules remain unchanged. Example native_buffer.doc calls actual POSIX read and write (x86_64 ssize_t maps to i64); DOC determines the output length from the returned input length, conditionally dispatches output, and returns partial-I/O status. It is not a retrying stream library. A typed exported DOC function can be registered as a compatible foreign callback or event entry; the caller owns storage/synchronization and invokes a fresh effect chain per event. No arbitrary callback signature, reentrant shared state or asynchronous retained buffer is admitted. A generic event driver or platform dispatcher can invoke such entries; a persistent DOC scheduler and general dynamic effect composition are required to be implemented and revalidated as DOC code in #11, not disguised as a permanent C application-policy loop. These are candidate changes until CI executes the direct I/O and negative fixtures.

### Native causal recurrence and region extent (#24 closure candidate)

`native repeat until HALT carry SOURCE=DERIVE[,SOURCE=DERIVE...]` repeats an authorized native dependency graph across causal epochs inside a single generated export. HALT must be a derived bool, each destination a unique named source, each carry value a matching derived int/bool (not a scoped acquisition). Every epoch evaluates the checked dependency graph; it completes its granted external effects and releases its invocation-scoped handles in reverse dependency order. If HALT is true, the final epoch's result struct is published; otherwise the scalar carry batch is applied simultaneously and a new epoch begins. External facts not carried retain the original invocation values. A failed epoch or exhausted 65,536-evaluated-epoch budget returns failure without publishing the result. Prior external effects are irreversible and never replayed; each iteration is an explicit causal execution, not a speculative retry or automatic reactive effect. No user-authored instruction loop, thread placement, or host stream policy is needed. A native scalar graph remains conservative and does not claim dynamic GPU placement. Foreign handles cannot be retained as managed DOC values; a carried scalar must not be used to evade the foreign ownership contract. The IR adds `repeat<TAB>halt-id<TAB>destination-id:value-id,...`; unsupported readers must reject it.

`native extent n: int (...) = REGION()` exposes the checked element capacity of a separately granted native region; it does not dereference the region, and counts greater than INT64_MAX reject. It is ordered in the native causal effect chain and uses the existing region-op IR row with opcode extent and no operands. This allows native DOC to check allocation/offset arithmetic against the real authorized region extent rather than trusting a separately supplied capacity integer. `native_arena.doc` implements a small checked offset-allocation policy and marks the last allocated byte; backing storage and base alignment remain privileged caller responsibilities. This is a constructive system allocator policy, not a new ordinary DOC manual allocator API or a full reclamation algorithm. `native_stream.doc` drives a variable-length real POSIX stream over a reusable buffer until DOC's derived terminal condition; the test oracle sets up pipes and verifies bytes, rather than implementing the loop. Native scoped cleanup is tested across multiple epochs, checked midstream failure and the exact recurrence bound. The native source/effect contract and its pure dynamic counterparts are the substrate for #11; the final independent DOC runtime must integrate these capabilities with its managed value and scheduler model, with no hand-authored portable policy or permanent Rust dependency.


### #15 worker-policy reconciliation

Stage-0 generated native frontiers and dependency families allocate worker metadata sized by the actual hardware/grain admission count; the former fixed 32-worker cap and game 256-request ceiling are removed. The current 4096-state/lane resource budget and minimum grain naturally bound per-frontier metadata to 128 slots, not a language-wide processor quota. Linux affinity detection supports larger dynamic CPU masks; inability to query capacity conservatively uses one worker. Thread creation fallback and all-candidate join/publication barriers are retained. The synthetic capacity-policy test verifies counts above 32 without claiming the CI machine actually has that many cores; real worker parity and allocation/lifetime tests remain mandatory. Production DOC scheduler still belongs to #11.
