## First executable slice

`compiler/lexer.doc` is DOC-authored, not a new Rust frontend or host parser. Given a sequence of UTF-8 byte values, a private causal scan emits immutable (token kind, byte offset, byte length) triples. Identifiers, decimal runs, quoted UTF-8 text, line boundaries, comments and punctuation are handled; invalid UTF-8, unsupported lexical bytes and unterminated/unsupported strings fail before the requested token result is published. Signs and arrow components are separate tokens. The current lexical profile is ASCII identifiers, no escape syntax, and no hash or line break in strings, matching the reference's line/comment restrictions. Syntax, numeric range, authority, typing, graph validity and import path semantics are later stages, not established by lexing.

The bootstrap test in `tests/test_lexer.py` uses a separate regular-expression oracle solely for testing. It compares actual token spans and invalid-input rejection under 1 and 4 worker settings, including the compiler source and an authored graphics stage; the native test invokes the generated executable from an empty directory. Frozen reference and actual native lexer passed 16 positive and 9 negative cases on commit 396807872f7f5c60414001cc619cfc3e4a1673fe, [CI 45542282787](https://github.com/rtu0/doc2/actions/runs/45542282787). The immutable recurrence uses bounded reference collections and copies growing state: no large-input or throughput claim, and it needs a production storage design. No Stage-1 self-hosting claim.

## Second executable compiler slice (candidate)

Shared pure DOC modules lexer_core.doc, parser_core.doc and scalar_core.doc are elaborated by the immutable Stage-0 compiler. parser.doc parses declarations, prefix calls, source-list syntax, function headers and import syntax into (tag, token ordinal, aux) event triples. It does not execute source or resolve imports. scalar.doc consumes the syntax events, resolves explicitly declared premises and prior symbols, rejects duplicate/self/forward/hidden references, checks exact int/bool operator arity and types, admits signed decimal values using checked negative accumulation, and emits C for actual DOC source/derive declarations with add/sub/mul/eq/lt/le/if. Generated C uses checked arithmetic, lazy conditional selection, internal identifier prefixes, normalized hex literals and prints only after all initial states succeed. No host parser or permanent interpreter in the emitted target program. Python is test-only.

Scope: initial complete stable valuation of the int/bool pure acyclic declaration subset, in topological source order. This is not the final dependency scheduler: no incremental updates/demand, parallel placement, collections/native effects/functions or self-compilation by the new compiler yet. Unsupported syntax or types are rejected; import syntax in the parser does not grant authority. Reference resource limits and immutable growing buffers remain temporary. Local frozen-reference tests: parser 19 positive and 17 negative, scalar 25 positive (16 generated), 3 runtime faults, 18 invalid and 7 unsupported. Actual emitted C compiled and ran under UBSan without DOC source files. Native compiler components passed exact CI [45543434087](https://github.com/rtu0/doc2/actions/runs/45543434087) at 41a46b0fe53b9964d629f21617367c2028faf6ae, same local case counts through both execution paths.

## Third executable slice (candidate): independent reactive scalar lowering

The DOC runtime planner (runtime/repair_plan.doc and repair_core.doc) validates topologically ordered CSR graph metadata and mask shapes, computes direct activation, strict active ancestors, ready frontiers, demand closure, legal nonempty selections, exact-cutoff propagation and successor materialization. Candidate value computation and protected physical publication remain caller obligations. Test-only oracle exercises all 64 ordered four-state DAGs with eight activity masks and randomized facts, plus repeated-premise and hidden-active-ancestor fixtures: 514 cases and 18 invalid cases on frozen reference.

compiler/reactive.doc extends the independently emitted int/bool native subset to repeated source updates, requested demand, exact cutoff, and actual dependency-minimal ready-frontier execution. DOC code generation specializes per-state C functions and direct edges for demand, blocking, activation and commit; generic C emitted by DOC provides checked word operations, CLI parsing and Linux thread admission/join substrate. All candidates read the same old valuation and write distinct private slots, thread-local checked failures reject the entire frontier before commit, and user observations occur only after successful demanded stabilization. Actual hardware affinity and a provisional 32-lane/16-lane-per-worker grain control worker count without arbitrary small worker caps. Local tests compiled/ran source-free native ELF with UBSan: 17 graphs, 64 worker/scenario executions; explicit 32-lane two-worker proof, failed wide frontier without new epoch, and unchanged-input zero evaluations. Native compiler and planner CI must verify the batch. This is a bounded scalar runtime, not final collection/region ownership, graph replacement, asynchronous cancellation, GPU or self-hosting. The new compiler does not yet compile its own full source; Stage-0 still builds it. Native C CLI/thread helpers are temporary emitted substrate; portable general runtime/lifetime policy must remain DOC-authored.

## Managed reactive lowering (candidate)

managed_reactive.doc emits graph-specific direct invalidation, reverse demand closure, active-ancestor blocking and ready-frontier selection from typed declaration identities. The provisional reactive_values.h platform substrate owns stable, speculative and candidate regions separately; only the coordinator changes visible slots, only after all launched workers join successfully. A failed epoch discards speculative regions and restores values and dirty/availability state, including updates from earlier successful private frontiers. Equal managed values stop propagation. Atomic counters measure allocation activity, not ownership. Local tests: 22 source-free native epoch comparisons against the frozen reference, sanitizer checks, actual 32-lane parallel frontiers, exact cutoff and same-process rollback/recovery. CI also exercises native compiler emission. Current implementation is bounded, synchronous, CPU-only and uses C platform coordination; asynchronous readers, device retirement/cancellation, topology changes, and fully DOC-authored portable coordination are still open.

## Portable placement policy and device-owned buffer reuse (candidate)

The generated DOC placement policy chooses worker count and device frontier route from admitted lane counts and hardware capacity. Checked-in macros are compared with actual compiler output; the decision matrix tests 1,246,979 combinations. The thresholds preserve the provisional profile (32 tasks before parallelism, 16 per CPU worker, 64 eligible GPU lanes for auto), not a universal profitability claim. The WebGPU substrate retains input/selection/output/staging buffers in a device-owned pool and grows only when needed. Successful mapped completion and unmapping precede reuse; output is explicitly zeroed before every dispatch so a stale marker cannot attest to a new result. Device/epoch failures stop publication. Actual-device pool reuse and output parity are required by the Stage-2 GPU tests; this is a candidate until those gates pass.

## Prelinked graph generations (candidate)

## Native checkpoint and committed audio boundary (candidate)

The independent reactive build embeds a SHA-256 of the compiler-admitted bundled source, not a path to the original source or evaluator. Optional `--output-root=DIR` is a separate explicit filesystem authority. During recurrence, `--save=RELATIVE.chk` persists only stable typed source facts, and `--load=RELATIVE.chk` restores them into an independently evaluated new epoch zero. The versioned DOC11CP1 format binds exact source bytes, ordered typed source identities and carry authority, bounds, and a corruption checksum (not authentication). It is intentionally distinct from the frozen Rust debug-IR checkpoint encoding; cross-format migration is not claimed. Defaults are sampled separately before applying restored facts. No derived values or host gameplay rules are loaded.

`--audio-dir=EXISTING_DIR` consumes the unchanged DOC graph's stable `audio_hz` and `audio_ms` cues after committed successors only, emitting actual 44.1-kHz mono PCM16 WAV files via the narrow platform math/file boundary. DOC-authored admission policy is regenerated by Stage 2. Confined descriptor-relative no-follow paths, bounded regular reads and same-directory temporary-file/rename publication reject traversal and special files. File publication is atomic per file, not a distributed transaction: an external effect failure does not undo an already committed pure epoch. Optional output authority is never implicit in asset read authority.

The game test requires original full replay parity, three split/restore comparisons, invalid checksum/schema/carry/type/length/path rejection before initial publication, successful typed prefab reload and atomic invalid-reload rollback, and sample-exact independent PCM verification. Native graph logic remains unchanged. The new file boundary passed a local ASan/UBSan ABI harness; integrated Stage-2 execution remains a CI gate.

### Native scalar regions (candidate)

The DOC-authored native compiler now admits the original frozen `native_regions.doc` alongside the plain-byte freestanding fixture: explicit distinct region grants, `u8 volatile`, `u32 atomic`, checked load/store/fetch_add, extent, and `seq_cst` fence. The emitted C has typed region accesses and checks alignment, byte extent overflow and disjointness from other admitted regions and the result record. A caller must still supply actual valid accessible storage with appropriate C atomic object lifetimes. External effects are irreversible; a later error prevents result-record publication but cannot retract an earlier device store. Hosted ASan/UBSan execution of Stage-2-emitted original region code passed locally; the new compiler negatives, wrap and effect tests and unchanged boot must pass CI. This is a bounded two-region scalar profile, not the complete system ABI or resource/FFI closure.

Checked `quot` and `bit_and` are now admitted by the scalar, reactive scalar and native object profiles. The original frozen `native_arena.doc` uses region extent, alignment and capacity decisions with DOC-controlled guarded arithmetic and checked writes; the local reference-candidate generated C passed a sanitizer host fixture. Stage-2 differential compilation and the expanded native/scalar CI remain required.

The compiled-game GPU validation also measures three complete CPU and three complete auto replays of the same GPU-enabled executable, exact typed-output parity, process peak RSS and tracked region usage. It records host-side device-open and per-dispatch wall time (including staging, submission, synchronization and readback), transferred bytes, pool capacity and cold/warm distributions. These are not isolated hardware-kernel timestamps or a claimed speedup; real software and physical-device results are still required.

### Independent native intrinsic profile

The DOC-authored native compiler admits the original frozen popcount, leading/trailing-zero and explicitly granted external-intrinsic examples. Built-ins use zero-safe 64-bit bit semantics, and the external profile is restricted to the declared `(i64,bool8)->i32` signature. The exported wrapper rejects invalid booleans and output pointers before an external side effect. This is a bounded declaration profile (one alias per built-in and one external grant), not generic FFI. The frozen reference evaluator reached its expression-specialization limit when evaluating this expanded compiler source; the independently reproduced Stage-2 compiler compiled the source directly and its generated code passed hosted sanitizer testing (4,162 bit patterns, external ABI checks, 20 rejected compiler requests). The independent CI lane builds from Stage 2, with no Rust source changes.

### Independent POSIX buffer profile

The original frozen native_buffer.doc is compiled by DOC Stage 2 using separate explicit `allow_read` and `allow_write` permissions. The generated ABI admits Linux x86_64 `read(i32,bytes)->i64` and `write(i32,const_bytes)->i64`, with a caller-owned plain byte region. DOC guard and fallback dependencies control the actual external calls. Selected calls check descriptor narrowing, signed offset/count and exclusive subrange bounds before forming pointers. Skipped calls do not check unused call arguments or invoke the external symbol. Errors do not publish a partial result record; irreversible external effects are not rolled back. Real POSIX pipes, short reads, EOF, guard skips and range failures passed a local ASan/UBSan host test; 20 malformed or ungranted compiler requests were rejected. The compiler reserves read/write in this bounded profile, which does not yet include native repeat or scoped cleanup.
